 trip-plan

把「我想去 X 玩 N 天」变成一份能照着走的行程报告。

纯规则引擎，零大模型依赖、零 API Key、离线可跑、30 秒出报告。
支持境内单目的地、多城市自驾、境外出行三种场景。



它解决什么

手工规划一趟旅行要干四件烦人的事，这个仓库把四件串成一条流水线：

| 痛点 | 怎么解决 |
|---|---|
| 攻略散落且互相矛盾 | 一次性跑 10 组查询模板（景点 / 门票 / 交通 / 美食 / 活动 / 避坑），结果统一入池 |
| 不知道信息能不能信 | 按域名把信源分成 A / U / C / D 四级，报告附完整 A 级信源清单可自己复核 |
| 景点排成会折返的动线 | 四阶段编排算法：名片保底 → 片区配额 → 配额执行 → 全局补位 |
| 算不清花多少、要预约什么 | 区间化预算（不编单一数字）+ 独立的「预约与限流」模块 |

它不解决什么

- 不做预订。没有实时库存与价格，费用只给区间，下单前须自行复核；
- 不做导航级精度。给的是景点顺序与片区，不是逐段交通方案；车程是估算值；
- 不做信息不可得的目的地。检索拿不到数据，规则引擎就无从规划。


快速开始

要求

Python 3.8+。就这样。

不装也能跑 —— 会自动降级到内置轻量转换器（没有模块导航和地图，但报告照样出）。

产物：

| 文件 | 内容 |
|---|---|
| `out/graded.json` | 检索结果 + 信源分级明细（A/U/C/D） |
| `out/places.json` | 抽取出的景点池（坐标、票价、建议时长） |
| `out/itinerary.json` | 逐日行程（含备选、预算、GCJ-02 坐标） |
| `out/报告_.md` | Markdown 报告（含模块标记与 `<details>` 折叠） |
| `out/报告_.html` | 交付物：模块化单文件 HTML + 内嵌 SVG 路线图 |

Windows 用户：双击 BAT

不用配环境，BAT 自带 Python 探测（PATH → 常见安装路径兜底）：

| 双击 | 作用 |
|---|---|
| `运行.bat` | 单目的地一键出报告 |
| `生成地图.bat` | 出路线图 / 把地图内嵌进报告 |
| `住宿层.bat` | 抓真实住宿点位 + 四档推荐 |
| `快速重排.bat` | 改天数 / 日期重跑（复用已检索数据，不重新联网） |
| `打包.bat` | 打成可搬运的 zip |

> ⚠ 不要只拷 `scripts/` 里的单个文件 —— 它们互相 `import`，必须整目录在一起。
> 脚本内无绝对路径硬编码，放任何位置都能跑。

报告长什么样

报告是模块化版面（顶部导航切换，不是一页到底）。单目的地典型 9 个模块：

> 概览 / 详细行程 / 城际交通 / 预约与限流 / 备选地点 / 费用 / 路线地图 / 行前与风险 / 信源与核查

叠加增强层后最多 11 个：+ 天气与装备 + 近期动向 + 拥挤度与错峰。


路线图为什么是 SVG 而不是交互地图

一开始做的是腾讯地图交互版，后来发现一个致命问题：它的代理地址依赖运行时注入，
而报告是静态 HTML 交付 —— 发给别人、离线打开、微信转发，全都白屏。

所以默认改成内联 SVG 两层分面示意图：

- 第一层：一天一格，每格各自比例尺（不让 125 km 的长途把 3 km 的城区段压成一团）
- 第二层：格内再按距离分簇 —— 一天里跑两个相距很远的片区时不会再画坏
- 跨城长途不上图，只在格底用文字交代里程与车程

代价是没有底图和道路几何；收益是零外部依赖、离线可渲染、能打印、静态托管不白屏、手机上能看。

工作原理

```
检索 ────→ 分级 ────→ 抽取 ────→ 编排 ────→ 报告
anysearch   A/U/C/D   规则引擎   规则引擎    MD + 单文件 HTML
匿名可用    域名判定   景点识别   地理聚类    + 内联 SVG 路线图
```

1. 信源四档 —— A（权威媒体 / 政府站 / 官方票务）直接采信，U（真实 UGC 笔记页）交叉印证，
C（境外 OTA / 旧帖）标注待核，D（地域无关）直接排除。
> 所以分级之后还需要一道「必须命中目的地名或别名」的过滤。

2. 规则抽取 —— 四层过滤：后缀严格判定（不做子串匹配）+ 句式碎片排除 +
繁简转换统一 + 白名单高置信度标记。处理"除了鲁迅故里和沈园"这类句子不会抽出半句话。

3. 四阶段编排（核心）

| 阶段 | 做什么 |
|---|---|
| 名片保底 | 城市必去景点无条件入选。它们在文本里可能缺 4A 标注导致被打分低估，不能靠分数决定去留 |
| 片区配额 | 按「价值密度 = 前 N 高点分数和 ÷ 所需天数 − 离城距离 × 0.28」给片区预留天数 |
| 配额执行 | 高密度片区先挑天，优先与已有同片区景点成组 |
| 全局补位 | 剩余容量按分数降序填，受「每天 ≤ N 个 + 单日跨度 ≤ 18 km」双约束 |


4. 远郊自动降级 —— 离城 > 45 km 的名片转入"一日游备选"。
单程 1.5 小时以上当天往返会挤掉市区体验，这是产品决策不是算法限制；行程天数变多时它会自动回归。


六个增强层（按需单独跑）

主流水线之外，这些层各自解决一个具体问题：

| 层 | 命令 | 解决什么 |
|---|---|---|
| 补查询 | `scripts/gapfill.py` | 「现在还开着吗 / 国庆要预约吗 / 最近在维修吗」—— 八方向情报缺口检测 + 相关性闸门 + 最多两轮定向补查 |
| 天气 | `scripts/weather.py` | Open-Meteo 免 Key。临行用预报；超窗口（如提前半年订票）用过往 5 年同期气候平均，给穿衣 / 带伞 / 防晒建议与雨天对调方案 |
| 拥挤度 | `scripts/crowd_research.py` | 针对小长假 / 暑期，逐景点研判拥挤程度、峰值时段与错峰建议，附替换矩阵 |
| 住宿 | `scripts/lodging.py` | Overpass（免 Key 全球）/ 高德（国内覆盖最好）；出「首选 / 升级 / 特色 / 预算」四档 |
| 地图 | `scripts/map_html.py` | `--mode svg` 零依赖（默认）/ `--mode tmap` 腾讯交互版 |
| 境外 | `scripts/overseas_research.py` | Photon 地理编码 + Overpass POI + OSRM 真实路网 + OpenFreeMap 底图，全免 Key 开源栈 |

详细用法见 [`SKILL.md`](SKILL.md)（完整手册，也是维护者文档）。

关于住宿价格的一句话说明

> 酒店"点位"能免费拿到，酒店"房价"没有任何免费开放接口。

盘点过 13 个数据源：Overpass 免 Key 可用但没有价格；高德 / 百度 / 腾讯 / 天地图都可申请免费 Key；
而携程 / 飞猪 / Booking / Expedia / Amadeus 全部要么需企业签约，要么需合作方凭据。

所以本层只输出档位区间，报告里强制标注"非实时报价、下单前须复核"。
这个项目不会为了让报告好看而伪造精确房价。


隐私

- 不采集、不上报任何个人信息，无埋点、无遥测。
- 检索关键词（含目的地与出行日期）会发送给检索服务商 anysearch —— 这是功能所必需，请知悉。
- 工具召唤提示 Key 会缓存到 `~/.anysearch_key`（在你的用户目录下，不在仓库里）。
  也可通过 `ANYSEARCH_KEY_FILE` 环境变量改位置。
- 天气走 Open-Meteo（免费免 Key），地图默认走内联 SVG（不请求任何外部服务）。

已知局限

诚实是这份报告最大的价值，所以局限也写清楚：

- 坐标表要手工维护。未收录的景点会落到"未定位"，评分降 2 分，通常进备选。
- 票价可能过时。数字从检索文本抽取，来源若是几年前的攻略就会偏差 —— 报告会标注待核。
- 活动排期最不可靠。拿不到当年节庆排期时，报告会明写"未能获取到确定性活动排期"，不会编造。
- 住宿是档位不是报价，这点前面说过了。
- 多片区模式需要人工指定每天在哪个片区（`DAY_PLAN`），算法不会自己推导日程锚点。
- 餐饮建议在单目的地模式下是模板生成的，按片区套用，不是真实店铺推荐。
- 境外有几个源在本网络环境不可达：整个 Wikimedia（含 Wikivoyage）、Nominatim、
  冰岛 `vedur.is` / `road.is` 都被墙或不可达。已有替代链路，详见 `references/境外行程扩展.md`。
- 补查询有额度成本。一次完整规划约 40~55 次检索调用；`check` 模式可先离线看缺口再决定补不补。
- 补查询召回质量不稳定。缺什么方向不等于搜得到 —— 永泰的「预约限流」补了两轮仍只有 1 条命中。
  脚本会如实标 `still_gap` 并在报告里写「信息有限」。
- 腾讯交互版依赖运行时注入。脱离原环境必然白屏 —— 所以默认改成了 SVG。交付一律用 SVG。

常见问题

Q：报告出来了但没有路线地图？
两种原因：① 没装 `markdown`（`pip install -r requirements.txt`）；
② 行程景点缺经纬度（单目的地模式依赖 `KNOWN_COORDS` 表）。补坐标即可。

Q：想换个目的地怎么弄？
算法层通用，改三张表即可（在 `scripts/planner.py`）：`CITY_CENTER`（必改）/ `REGIONS` /
`KNOWN_COORDS` / `MUST_SEE`。坐标用 GCJ-02。完整步骤见 `references/换城市指南.md`。

Q：手机上能跑吗？
不能（要 Python + 联网检索）。但成果能在手机上看 —— 这正是地图做成内联 SVG 的原因。
把 `报告_.html` 或独立 SVG 路线图发进微信就能直接读。别发腾讯交互版，那是白屏。

Q：Windows 下双击 BAT 闪退？
多半是换行符。clone 后请确认 `.gitattributes` 未被忽略 —— BAT 必须是 CRLF，
LF 结尾的 BAT 在中文 Windows 上会乱码或吞命令。
