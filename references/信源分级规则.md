# 信源分级规则

`research.py` 的 `grade_source()` 按来源域名和发布日期给每条检索结果打等级。这个判断决定了信息后续是被直接采信、标注待核、还是直接丢弃。

## 三档定义

| 等级 | 含义 | 报告中的处理 |
|---|---|---|
| **A** | 权威可采信 | 直接写进报告，列入" A 级信源清单"（带链接可复核） |
| **C** | 可用但需核对 | 采信内容，但标注"信源时效需现场核对" |
| **D** | 噪声，直接排除 | 不进入景点池；在报告的"被排除条目"里列出，说明为什么排 |

## 判定顺序

`grade_source()` 是**有顺序的**，先匹配先生效：

```
1. GEO_NOISE   → D    地域噪声（最高优先级，一票否决）
2. OTA_DOMAINS → C    境外 OTA / 繁体站
3. gov.cn      → A    官方政府来源
4. AUTHORITY   → A    境内权威媒体
5. STALE_YEARS → C    内容可能过时
6. 兜底         → C    待人工复核
```

**顺序为什么重要**：某条结果可能同时命中 `trip.com`（OTA）和日期含 `2019`（过时）。先判 OTA 会得到 C，理由是"境外OTA"；如果先判年份会得到 C，理由是"内容过时"。这两个理由对用户的提示价值不同——前者提醒"这个平台的票价体系不用"，后者提醒"价格要重新查"。所以把域名判断放在前面。

## 各清单详解

### GEO_NOISE —— 地域噪声

```python
GEO_NOISE = [
    "discoverhongkong", "taichung", "ntua.edu.tw", "kcginfo", "gov.tw",
    "hktb.com", "nmtl.gov.tw", "th.trip.com", "partnernet",
]
```

**为什么需要这一档？** 检索"绍兴 活动 展览"时，anysearch 返回过台南的活动汇总表（`nmtl.gov.tw` 是台湾文学馆）。这类结果标题看起来是"节庆活动整理"，与查询意图高度匹配，但地理上完全不相关。如果不排除，会被当成"绍兴的国庆活动"写进报告。

**识别特征**：`.tw` 域名、境外旅游推广局（`discoverhongkong`、`hktb`）、境外 OTA 的东南亚分区（`th.trip.com`）。

实测：80 条结果里命中 3 条 D 级，全部是台湾来源的活动汇总。已从景点池排除。

### OTA_DOMAINS —— 需交叉验证

```python
OTA_DOMAINS = [
    "trip.com", "ctrip.com", "qunar.com", "kayak", "expedia", "booking.com",
    "agoda", "tripadvisor", "wingontravel", "eztravel", "skyscanner",
    "railmonsters", "hk.", "tw.", "sg.", "my.", "au.", "cn.tripadvisor",
]
```

**为什么标 C 而不是 A？** 两个原因：

1. **繁体站点的信息口径可能不同**。`hk.` / `tw.` 前缀的携程页面常常是繁体版，票价用港币/新台币标注，需要换算和核对。
2. **OTA 的内容常有缓存**。抓取的攻略文章可能是几年前的，票价、开放时间都已变更。

**注意**：`ctrip.com` 和 `trip.com` 是同一家的不同品牌，携程主站（简体）信息质量其实不错。但既然无法逐条判断具体页面质量，统一标 C + 提示核对是更安全的策略。

实测：55 条 C 级里，OTA 来源占绝大多数。

### AUTHORITY —— 权威来源

```python
AUTHORITY = [
    "zj.news.cn", "xinhuanet", "zjol.com.cn", "bendibao", "chinadaily",
    "cnr.cn", "baike.baidu", "amap.com", "163.com", "qq.com", "sohu.com",
    "zhihu.com", "people.com.cn", "sina", "cctv", "12306",
]
```

分级依据：

| 类别 | 域名 | 可信度理由 |
|---|---|---|
| 官方通讯社 | xinhuanet, news.cn, people.com.cn, cctv, cnr.cn | 一手信源，编辑审核严格 |
| 地方党媒 | zjol.com.cn（浙江在线）, chinadaily | 本地信息最准确 |
| **本地宝** | bendibao | **专做本地生活信息，票价/预约/交通的数据维护及时，是规划类任务的最佳信源** |
| 地图 | amap.com（高德） | POI 坐标和营业时间权威 |
| 百科 | baike.baidu | 背景信息可靠，但时效性差，需注意 |
| 门户 | 163.com, qq.com, sohu.com, sina | 转载为主，但常保留原始来源信息 |
| 社区 | zhihu.com | 质量参差，但优质攻略的信息密度高 |
| 铁路 | 12306 | 车次和票价的唯一权威来源 |

**本地宝为什么特别重要**：它专门维护"XX 景区门票多少钱、怎么预约、几号线能到"这类信息，且更新频繁。规划行程需要的正是这些数据。实测 23 条 A 级结果里，本地宝贡献了多条直接可用的票价和交通信息。

**zhihu.com 的争议**：知乎攻略质量方差很大。但设成 A 的理由是——优质回答（如"绍兴地铁 1 号线支线开通"这种带具体日期和站点名的内容）信息价值极高，而噪音内容会在"抽取层"被景点识别规则过滤掉。分级和抽取是两道独立的关卡。

### STALE_YEARS —— 时效预警

```python
STALE_YEARS = ["2010", "2011", "2017", "2018", "2019", "2020", "2021"]
```

匹配文章日期字段。命中则标 C，理由"内容可能过时"。

**为什么这些年份？** 2021 年及以前的内容，经历了疫情后的景区政策调整（预约制普及、部分票价变动），信息不可直接采信。2010-2011 是更早的旧帖，票价差距可能达数倍。

**局限**：很多检索结果没有日期字段，这一档命中率不高。实际上"内容过时"的判断更多依赖用户自己看链接日期——所以报告会把 A 级信源链接全部列出，让用户能点进去看。

## 抽取层的第二道过滤

分级只处理"来源可信度"，不处理"内容是否是一个景点"。所以还需要 `extract.py` 的独立过滤：

| 关卡 | 作用 | 例子 |
|---|---|---|
| 信源分级 | 这条结果可不可信 | `nmtl.gov.tw` → D，排除 |
| 名称后缀 | 这是一个景点名吗 | "除了魯迅故里和沈園" → 不以景点后缀结尾，排除 |
| 句式排除 | 这是句子碎片吗 | "行程涵盖鲁迅故里" → 命中 `EXCLUDE_PATTERNS`，排除 |
| 繁简统一 | 是同一个地方的变体吗 | "黃酒博物馆" → 转"黄酒博物馆" |
| 白名单 | 是可靠地点吗 | 命中 `KNOWN_SPOTS`（34 个绍兴地点）→ `confidence: high` |
| 行程外剔除 | 属于本次行程吗 | "上海虹桥""西湖" → 命中 `OFFROUTE_EXACT`，排除 |

**实测效果**：80 条原始结果 → 抽取出 62 个干净景点（34 高置信 + 28 中置信）。中间经历过 80 → 44 → 62 的三轮调优，具体记录见 `算法设计.md`。

## 维护建议

### 什么时候需要加 GEO_NOISE

发现报告里出现**与目的地无关的城市/地区**内容时。典型信号：查 A 城市却返回 B 城市的活动表、政府公告。

### 什么时候需要加 AUTHORITY

发现某类来源的内容质量持续很好时。判断标准：**该来源是否维护了规划任务需要的数据**（票价、预约、交通、开放时间）。

### 什么时候需要调 STALE_YEARS

当"当前年份 − 3"之后的内容开始出现明显偏差时。例如现在是 2026 年，如果 2023 年的票价信息已经不准，就把 2023 加进去。

### 不建议做的事

**不要为了"提高 A 级比例"而放宽 AUTHORITY**。A 级比例本身不是目标——报告的价值在于"信源可复核"，不在于"看起来权威"。实测 23/80 = 29% 的 A 级比例是健康的：核心信息（票价、交通、必去景点）来自 A 级，补充信息来自 C 级并标注核对。
