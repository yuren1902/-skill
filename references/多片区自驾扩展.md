# 多片区 / 自驾扩展指南

原版 `planner.py` 是**单目的地模型**——它假定所有景点围绕一个 `CITY_CENTER`，按"片区价值密度"竞争固定的 N 天。

当行程满足以下任一条时，需要改用 `planner_multi.py`：

- **多城市联游**（上海 → 上虞 → 新昌）
- **有硬性日程锚点**（"9/30 晚出发""10/2 下午到 X""5 日必须返程"）
- **自驾**（地理跨度可放大，且需要油费/过路费/停车估算）
- **每日时间不均匀**（有半日、有全天）

## 与原版的核心差异

| 维度 | `planner.py`（原版） | `planner_multi.py`（扩展） |
|---|---|---|
| 目的地 | 单城市 | 多片区，各自独立锚点 |
| 天数分配 | 算法按密度自动决定 | **由 `DAY_PLAN` 显式指定每天在哪个片区** |
| 每日约束 | `PER_DAY=4` 个数上限 | **时间预算**（分钟数）+ 个数 + 大体力点配额 |
| 半日支持 | 无 | `ratio` 字段（1.0 全天 / 0.5 半日） |
| 排除机制 | 无 | `excl` 字段（如返程日只排县城内点） |
| 动线排序 | 按分数 | **最近邻**（从片区质心最远点起，避免折返） |
| 交通 | 高铁 | 自驾，含油费/过路费/停车 |

## 三个必须理解的约束层

### 1. 时间预算 > 个数上限

原版用"每天最多 4 个点"控制节奏。但这在多片区场景会失效——

**实测翻车案例**：新昌的「天姥山」（240 分）和「十九峰」（240 分）地理上只隔 10 km，
符合原版的跨度约束，于是被排进同一天。但这两个点**各自就要一整个白天**，
4 个"点"的计数完全掩盖了体力消耗。

修正：引入 `DAY_MINUTES_BUDGET`（默认满日 420 分钟）与 `BIG_SPOT_MIN`（150 分钟），
**单日 ≥150 分钟的大体力点最多 2 个**。

> ⚠️ **两条必须写清楚的补充（2026-09-15 宜兴案例新增）**
>
> **(a) 预算只算"净游览时长"，不含车程。**
> 自驾场景景点间车程累计常达 60~100 分钟/天。宜兴实测 4 天累计车程 220 km / 约 320 分钟，
> 日均 80 分钟驾驶。若按 420 分钟净游览 + 80 分钟车程 = 500 分钟，加上三餐与取还车，
> 实际耗时逼近 11 小时/天。**不要在报告里把这 420 分钟说成"全天时长"**，否则是误导。
>
> **(b) 每日点数上限是独立的第二把锁（先生规范）。**
> 时间预算管的是"体力"，点数管的是"节奏"。**一般一天不超过 6 个景点；
> 亲子游应更少**（建议 ≤3~4）。宜兴 4 日成人行程取 `PER_DAY=5`、半日取 3。
> 实现：`PER_DAY` / `PER_DAY_KIDS` 两个常量 + `KIDS_MODE` 开关，
> 半日 `cap_count = max(2, round(per_day * ratio))`。

```
can_add(p) 的四重门：
  1. len(picked) < cap_count                      # 点数上限
  2. spent() + p.duration <= budget               # 时间预算
  3. p 是大点 ? big_count() < 2 : True            # 大体力配额
  4. 与已选点最大距离 <= MAX_DAY_SPAN_KM           # 地理跨度
```

### 2. `DAY_PLAN` 是显式的，不是推导的

先生给的日程锚点（"9/30 晚出发""10/2 下午到新昌"）**不是算法能猜出来的**，
必须写成显式配置：

```python
DAY_PLAN = [
    {"idx": 0, "date": "2026-09-30", "district": None, "ratio": 0.0, ...},
    {"idx": 1, "date": "2026-10-01", "district": "上虞", "ratio": 1.0, ...},
    {"idx": 2, "date": "2026-10-02", "district": "新昌", "ratio": 0.5,
     "excl": ["十九峰", "天姥山", ...]},          # 半日不给大点
    ...
]
```

**为什么要 `excl`**：10/2 下午才到新昌，只有 3~4 小时可用。
如果不排除大点，算法会把十九峰塞进来（它分数最高），但实际根本走不完。

### 3. 特殊 district 名可以表达"约束"

`"新昌收尾"` 这个 district 名不是真实片区，而是**一个约束谓词**：

```python
if dist == "新昌收尾":
    # 只能用该片区"县城"区域内的点（返程日不顺路的不排）
    pool = [p for p in pools["新昌"] if p["_region"] == "新昌县城"]
```

这样做的好处是**不用给算法加新字段**，用命名就能表达意图。

## 陷阱记录

### 陷阱 1：点数上限掩盖体力消耗

见上文"时间预算"一节。**这是多片区自驾最容易翻车的地方**。

### 陷阱 2：返程日排了不顺路的点

初版把「越剧小镇」（距新昌县城 11.7 km）排进了 10/5 返程日上午。
它分数不低，地理跨度也不大，但**方向与返程相反**——上午去一趟再折回，
等于白跑 24 km。

修正：把越剧小镇、达利丝绸世界等加入返程日的 `excl`，同时用
`district="新昌收尾"` 限制只取县城内点。

### 陷阱 3：山区跨度无法消除，只能如实标注

上虞「覆卮山」距城区 22 km，是本次跨度最大的单日。
但它是上虞唯一的招牌级自然景观，**不可能因为远就不排**。

处理方式：不强行压缩，而是在报告里**如实标注跨度 + 给错峰建议**
（"建议 8:00 前上山，停车位有限"）。算法约束是为了"避免不必要的折返"，
不是"消灭所有长距离"——这是产品判断，不是机械规则。

### 陷阱 4：重复 append 导致输出翻倍

改动 `planner_multi.py` 的逐日分配循环时，曾在同一缩进层级留下两段
`scheduled.append(...)`，结果每天输出两遍。

**自查方法**：`grep -n "scheduled.append" planner_multi.py` 应该只出现
两处（一处是空白天、一处是正常日）。

## 陷阱 5：跨省/跨市边界片区，最近邻判定会串片区 —— `_region_hint` 修法

**症状**：宜兴案例中，「宜兴竹海」(119.679, 31.160) 距溧阳南山片区中心
(119.465, 31.160) 约 21 km，而距本应归属的"宜兴竹海区"中心 (119.670, 31.170) 仅 1.3 km。
本例侥幸正确，但 **宜兴云湖/太华一带与溧阳南山、长兴边界犬牙交错**，
`assign_region()` 的"最近中心"判定迟早会把景点划到隔壁县市。

**为什么这次特别危险**：跨市片区会直接改变行程结构——
一旦「宜兴竹海」被判到"溧阳"，它就会从 10/04 的竹海日消失，被塞进某个溧阳日，
或者永远进不了主行程。

**修法**：在景点池里加 `_region_hint` 字段**显式指定归属**，planner 优先用它：

```python
def P(name, t, price, dur, note, region=None, zone=None):
    return {..., "_region_hint": region, "_city": zone or "宜兴"}

# planner 侧
hint = p.get("_region_hint")
if hint:
    p["_region"] = hint                    # 显式优先
else:
    p["_region"], p["_region_dist"] = assign_region(*p["_coord"])   # 回退最近邻
```

**什么时候必须用**：只要目的地存在"边界地带"（邻市接壤、跨省交界、同名片区），
就应当显式指定，不要依赖最近邻。回退机制保留给确定不会歧义的点。

## 陷阱 6：报告篇幅失控 —— 四条压缩规范（先生 2026-09-15 指示）

第一版宜兴报告 30,467 字符，先生反馈"篇幅太长"。压缩到 13,581 字符（45%）后仍保留全部表格。
四条可复用规范：

> **总原则：报告要给结论，不要给推导过程。**
> 凡是"逐个 X 的详细研判"这类明细，读者多数时候只想扫一眼结论，真正要细看时才展开。
> 因此 —— **结论入正文，论据进折叠。**

**(a) 删除"生成方式"这类元信息行。**
报告正文不该出现"本报告由 X 引擎生成""零 LLM 依赖"之类的自我说明——
用户要的是行程，不是实现细节。放在文末的 italics 小字或干脆不写。

**(b) 信源清单必须折叠。**
A 级信源有 10~30 条，平铺会占掉 1/4 篇幅。用 `<details>` 折叠：

```markdown
<details>
<summary><b>A 级信源清单（点击展开）</b></summary>

- [标题](url)
- ...

</details>
```

⚠️ **HTML 转换的坑**：Python-Markdown 会把 `<details>` 当普通文本转义，或因为块内空行
被打断。正解是**先摘出来转成占位符，渲染后再回填**：

```python
def _extract_details(text):
    blocks = []
    def repl(m):
        blocks.append(markdown.markdown(m.group(1).strip(),
                                        extensions=["tables", "sane_lists"]))
        return "\n\n@@DETAILS_%d@@\n\n" % (len(blocks) - 1)
    text = re.sub(r"<details>(.*?)</details>", repl, text, flags=re.S)
    return text, blocks

# 渲染后回填，并把第一个 <p> 改写成 <summary>
for i, blk in enumerate(blocks):
    blk = re.sub(r"^<p>(.*?)</p>", r"<summary>\1</summary>", blk, count=1, flags=re.S)
    body = body.replace("@@DETAILS_%d@@" % i, '<details>%s</details>' % blk)
```

配套 CSS 让 summary 有折叠箭头与 hover 反馈（见 `md2html.py` 的 `details>summary` 规则）。

**(c) 备选池分层：主要备选成表，次要备选只写文字。**
第一版把 24 个备选全做成表格，占掉大量篇幅。改为：

| 层 | 数量 | 呈现 |
|---|---|---|
| 主要备选 | ≤8 个 | 表格（片区/时长/门票/简评），够替换主行程用 |
| 次要备选 | 其余全部 | **按片区归并成一句话**，用 `、` 分隔，如"宜兴城区：东坡书院（40min，免费）、宜兴市博物馆（60min，免费）……" |

```python
ALT_MAIN_N = 8
for p in alts:
    big = (p["_score"] >= 6.0
           or p["_district"] in ("溧阳", "长兴")
           or p["duration_min"] >= 150)
    if (big and len(main_alts) < ALT_MAIN_N) or len(main_alts) < 4:
        main_alts.append(p)
    else:
        minor_alts.append(p)
```

**(d) 逐条明细必须折叠（4.1 逐个研判）。**
拥挤度章的"逐个景点研判"是 10 个景点 × 5 行表格，平铺占掉整屏。
正文只留**结论性内容**——总原则（4.2）与替换矩阵（4.3）；逐个明细整块塞进 `<details>`：

```markdown
### 4.1 主行程景点逐个研判

<details>
<summary><b>展开查看 10 个景点的逐个研判</b>（峰值时段 / 建议到达 / 避开时段 / 排队量级 / 实操建议）</summary>

#### 善卷洞 ｜ 拥挤度 ●● 极高

| 维度 | 研判 |
|---|---|
| 峰值时段 | ... |

（其余景点同构）

</details>

### 4.2 错峰五条总原则
```

⚠️ **`<details>` 内套 h4 + 表格时，CSS 要补规则**，否则 h4 会紧贴边框、表格宽度撑破容器：


**小结：可折叠的四类内容** —— ① 元信息（直接删，不折叠）② 长信源清单 ③ 逐条明细 ④
低频参考数据（票价表、预约政策原文）。**不可折叠的**：一图速览、逐日动线、预算、
错峰总原则——这些是用户真正要"扫一眼"的东西。

## 新增能力：拥挤度 / 错峰研判（`crowd_research.py`）

先生 2026-09-15 要求：**更多获取小红书、大众点评、携程、飞猪、去哪儿、游侠客等公开信源的
最新信息**，针对小长假与暑期游给出**景点拥挤程度与错峰建议**。

### 为什么 `research.py` 不够

`research.py` 走的是"城市维度的 17 组通用查询"，用来**建景点池**。
但拥挤度是**景点维度**的问题——必须对每个景点单独问"人多吗/几点去人少/怎么避雷"。
两者查询意图正交，不能复用。

### 用法

```bash
python crowd_research.py --spots "善卷洞,宜兴竹海,窑湖小镇" --out ./crowd
```

- 每个景点 3 条拥挤度通用查询 + 每平台 2 条 `site:` 定向 = 3 + 6×2 = 15 条/景点
- 输出 `crowd/raw.json` + `crowd/graded.json`（带 `platform` / `spot` / `kind` 字段）
- `--no-site` 可跳过平台定向（只跑通用拥挤度查询）

```python
CROWD = {
    "善卷洞": {
        "level": "极高", "level_n": 4,          # level_n 用于徽章与替换矩阵
        "peak": "10:00-14:00（国庆为全年峰值段）",
        "go": "**07:30 前抵达**（开放 07:30~17:00，第一批进洞）",
        "avoid": "10:30-15:00 抵达；停车场与换票队列同时满载",
        "queue": "换票窗口峰值排队 30~60 分钟；水洞乘船段是最大瓶颈",
        "tip": "网购票免换票队列；进洞后先直奔水洞船码头再回看钟乳石",
        "src": "本地宝 / 大众点评 / 携程 / 游侠客 / 小红书",
    },

```

**关键**：`src` 字段必须如实标注情报来自哪些平台，便于用户复核。
**不要编造排队时长**——只写检索到的原话或有出处的量级。

### 错峰研判的五条总原则（可跨目的地复用）

1. **早出发是唯一通用解** —— 主力景区拥堵曲线普遍是"10:00 起飞、14:00 见顶、16:30 回落"，
   08:00 前抵达可在峰值到来前走完核心游线
2. **双高峰避开** —— 上午 10:00-12:30（团队客）与下午 14:00-16:00（自驾客）；
   **12:00-13:30 是全天最空的午餐窗口**，用于转场等于凭空多出 1.5 小时
3. **停车是隐性瓶颈** —— 把"到停车场"而非"到景区门口"当时间节点，
   否则上午计划会被停车吃掉（满位后常需步行 10~15 分钟）
4. **夜场是错峰的隐藏机会** —— 有夜场的景区，最空的是白天段而非夜场段
5. **用"低热度同质景点"替换高峰点** —— 报告应给出**按拥挤度的替换矩阵**，
   例如"竹海爆满 → 龙池山自行车公园""窑湖夜场爆满 → 团氿风景区"

### 季节性内容的诚实标注

拥挤度之外，**季节陷阱也要如实标注**（同类于上虞杨梅、盖北葡萄）：
宜兴十里古银杏长廊最佳期是 **11 月中下旬**，10 月上旬仅初黄——
必须写"不是最佳期"，而不是隐瞒或含糊带过。

## 换城市/换行程要改什么

| 位置 | 文件 | 内容 |
|---|---|---|
| 坐标表 | `places_multicity.py` → `COORDS` | 景点 → (经度, 纬度)，GCJ-02 |
| 区域表 | `places_multicity.py` → `REGIONS` | 功能分区 + 中心坐标 + 半径 |
| 名片清单 | `places_multicity.py` → `MUST_SEE` | 按片区组织 |
| 景点池 | `places_multicity.py` → `PLACES` | 含票价、时长、备注 |
| **片区归属** | `places_multicity.py` → `P(region=...)` | **边界地带必须显式指定（见陷阱 5）** |
| 片区锚点 | `planner_multi.py` → `DISTRICT_ANCHOR` | 每个片区的中心 |

| 住宿 | `report_multi.py` → `HOTELS` | 分段的住宿建议 |

| **拥挤度研判** | `report_*.py` → `CROWD` + `PEAK_RULES` | **逐景点峰值/错峰/排队量级 + 替换矩阵** |
| **模块切分** | `report_*.py` → `<!--MODULE:名称:图标:简介-->` | **4~6 个模块，见下节** |
| **地图配色** | `map_html.py` → `DAY_COLORS` | 逐日折线颜色，天数 >6 需扩充 |

算法层（`plan()` 函数）**不需要改动**。

## 新增能力：模块化版面（不做"一页到底"）

先生 2026-09-15 指示：**整个版面排布不要一页式的，改为 4-6 个模块**。

### 机制

报告 Markdown 里插一行注释标记开一个新模块，`md2html.py` 解析后渲染成
**顶部粘性导航 + 可点击切换的模块卡片**：

```markdown
<!--MODULE:概览:◎:一图看懂这趟行程-->
## 〇 一图速览
...正文...

<!--MODULE:详细行程:▤:逐日动线 · 到达时刻 · 拥挤度 · 时长-->
## 一 逐日行程
...
```

切分规则：

1. 一行 `<!--MODULE:名称:图标:简介-->` 开启模块，到下一个标记为止。
2. **图标用一个字符**（`◎ ▤ ￥ ◐ ◇ !`），不要用 emoji —— 跨平台字体渲染不一致。
3. 模块内**首个 `## 标题` 会被自动剥掉** —— 模块名已承担这个职责，
   否则会出现"模块名 / 章节名"重影（导航写"详细行程"，下面又写"一 逐日行程"）。
4. 模块内次级标题从 `###`（h3）起。
5. 第一个标记之前的内容当作**前言**，其中 `>` 引用块会进封面副标题区。

### 宜兴实例的 6 模块划分

| 模块 | 图标 | 归并了哪些章节 | 正文体量 |
|---|---|---|---|
| 概览 | ◎ | 一图速览 + 四天一句话 + 地图入口 | 1.2K |
| 详细行程 | ▤ | 逐日行程 | 4.5K |
| 费用与交通 | ￥ | 城际交通 + 门票预约 + 预算 + 住宿 | 2.5K |
| 拥挤度与错峰 | ◐ | 4.1 折叠 / 4.2 总原则 / 4.3 替换矩阵 | 6.8K |
| 备选地点 | ◇ | 主要备选（表）+ 次要备选（文字） | 3.2K |
| 行前与风险 | ! | 时效风险 + 信源说明 + 7 日清单 | 4.1K |

**划分思路**：把"用户会一次性看完"的内容聚到一个模块，把"要查才看"的
（拥挤度明细、备选、信源）单独成模块。不要把 10 个章节原样做成 10 个模块
—— 那样导航反而更长。

### 坑

- **模块名不要与章节名重复**。已自动剥掉首个 h2，但如果你在模块里再写一个
  同义的 h3（如模块"备选地点"下写"### 五 备选地点"），重影依旧。改成
  `### 5.1 主要备选` 这种带语义的小标题。
- **表格要横向滚动**：`md2html.py` 会把 `<table>` 包一层 `<div class="tw">`
  （`overflow-x:auto`），否则宽表在窄屏会撑破卡片。
- **打印要展开**：CSS 里 `.mod{display:none}` 在 `@media print` 下改为
  `display:block !important`，否则打印只出一页。

## 新增能力：可视化地图（`map_html.py`）

先生 2026-09-15 指示：**最好加一个可视化地图，方便看具体景点间的路线和距离，
地图数据找找高德和百度地图的公开端口吧**。

### 先说合规：为什么没走高德/百度

实测（2026-09-15，本沙箱环境）：

| 接口 | 结果 |
|---|---|
| 高德 REST `restapi.amap.com/v3/geocode/geo?key=test` | 网络通，返回 `{"status":"0","info":"INVALID_USER_KEY"}` |
| 高德 JS API `webapi.amap.com/maps?v=2.0&key=test` | 返回 `<AMap JSAPI> Error key!` |
| 高德静态图 `v3/staticmap` | HTTP 200，但响应体是 JSON 错误（59 字节），不是图 |
| 百度静态图 `api.map.baidu.com/staticimage/v2?ak=test` | `{"message":"APP不存在，AK有误请检查再重试"}` |
| 百度 JS API `api.map.baidu.com/api?v=3.0` | HTTP 200（JS 加载可达，但需有效 AK） |

**结论**：两家的接口网络都通，但**都要有效 Key**。按 `geo-map-compliance-guard`
规范，模型**不得内置任何 Key**。因此改用腾讯地图的**官方免 Key 代理模式**
（`_TMapSecurityConfig`）—— 由 WorkBuddy 后端持 Key、前端零暴露，开箱即用。

### 兜底方案（若先生自有 Key）

若先生有自己的 Key，把 SDK URL 改成显式占位符形式：

```html
<script src="https://map.qq.com/api/gljs?v=1.exp&key=请到腾讯位置服务开放平台申请后替换"></script>
```

或切高德/百度（同样写显式占位符，不要写死真 Key）：

```html
<!-- 高德 -->
<script src="https://webapi.amap.com/maps?v=2.0&key=请到高德开放平台申请后替换"></script>
<!-- 百度 -->
<script src="https://api.map.baidu.com/api?v=3.0&ak=请到百度地图开放平台申请后替换"></script>
```

### 地图要素

| 要素 | 实现 | 备注 |
|---|---|---|
| 逐日路线 | `TMap.MultiPolyline`，按天分色 | `DAY_COLORS` 六色循环 |
| 主景点 | `TMap.MultiMarker` + **内联 SVG 水滴图标** | 不引用官方 demo 图（规范明令禁止） |
| 行程锚点 | 车站单独样式（深色 + 列车图形） | 首末两天折线连到车站 |
| 主要备选 | 半透明小圆点 | 便于临时替换时参考位置 |
| 距离标签 | 相邻两点**直线距离** + 车程估算 | 直线 = haversine；车程 = 直线×1.35÷45km/h |
| 侧栏 | 逐日卡片，点开看点位与逐段距离 | 手机端自动改为上地图下侧栏 |
| 视野 | `map.fitBounds(...)` | 自动包住全部点 + 车站 |

### 坑（全部已在脚本里规避）

1. **`_TMapSecurityConfig` 必须在 SDK `<script>` 之前** —— 否则地图空白。
2. **SDK URL 不能带 `?key=`**，也不能额外调 `TMap.setConfig()` —— 两者同用会白屏。
3. **不要用 `mapStyleId`** —— 自定义样式需在控制台单独开通，默认 Key 不支持，
   误用后底图变灰。`new TMap.Map()` 不传该参数即用默认矢量底图。
4. **容器必须有固定高度**（`height:100vh` 或像素值），否则不渲染；flex 布局下尤其注意。
5. **不要手工 `fetch(serviceHost + '&path=...')`** —— 路由规划要走
   `TMap.service.Driving`、POI 搜索走 `TMap.service.Search`（需在 SDK URL 加
   `libraries=service`），SDK 内部会自动走代理。手工拼 URL 会得到
   LatLng NaN / 403。
6. **路线策略用字符串**：`new TMap.service.Driving({ policy: 'LEAST_TIME' })`，
   合法值 `LEAST_TIME` / `LEAST_DISTANCE` / `AVOID_HIGHWAY` / `REAL_TRAFFIC`。
   不要用 `TMap.constants.DRIVING_POLICY.xxx`。
7. **GL JS 类名规律**：图层类带 `Multi` 前缀（`MultiMarker` / `MultiPolyline`），
   样式类不带（`MarkerStyle` / `PolylineStyle`），服务类为 `TMap.service.Xxx`。

### 诚实性要求

- 折线是**点对点直线**，不是道路路径。报告与图注都要写明"实际请以导航为准"。
- 车程按 绕行系数 1.35 / 均速 45 km/h **估算**（宜兴丘陵路网经验值），
  不是导航数据。平原可降到 1.2，山区提到 1.5+。
- 要真实道路路径需接 `TMap.service.Driving`，会显著增加请求数与渲染时间，
  行程点数少（<15）时可考虑。

## 陷阱 7：小红书（UGC）根本不会被检索到 —— 实测与修法

**症状**：报告第八节信源清单里全是 hk.trip.com / 携程 / 本地宝 / 知乎，**一条小红书都没有**。
用户质问"你这个信息来源怎么没有小红书？"

**实测证据（2026-09-15，可复现）**

| 场景 | 结果 |
|---|---|
| 默认 10 组通用查询词，三片区 | 120 条结果中，小红书域命中 **仅 1 条** |
| 默认查询源的构成 | `hk.trip.com` 13、`wingontravel` 6、`gs.ctrip.com` 4、`youtube` 4、`12306` 7 |
| 追加 `site:xiaohongshu.com` 定向查询后 | 408 条结果中，小红书域命中 **8 条** |

**三层根因**

1. **查询词没点名** —— `{城市} 景点 必去 推荐` 这类通用词，搜索引擎按权重给 OTA 和知乎，小红书排在后面，进不了前 8。
2. **小红书页面依赖登录** —— 抓到的笔记页大多返回 `No information is available for this page`，摘要为空，没有可用信息。
3. **分级表没给小红书留位置** —— 旧 `AUTHORITY` 白名单有知乎/163/搜狐，没有小红书，它只能落到兜底 C。

**修法（已在 `research.py` 落地，默认生效）**

1. **新增 U 级（用户实拍）** —— 介于 A 与 C 之间的独立档：

```python
UGC_DOMAINS = ["xiaohongshu.com", "rednote.com", "xhslink.com",
               "dianping.com", "meituan.com", "bilibili.com", "douyin.com"]
```

2. **新增 UGC 定向查询包**（`QUERY_PACKS["ugc"]`，4 条，默认开启）：

```
site:xiaohongshu.com {city} 攻略
site:xiaohongshu.com {city} 美食
{city} 小红书 攻略 笔记
{city} 小红书 探店 实拍
```

`build_queries(..., include_ugc=True)` 控制；CLI 加 `--no-ugc` 可关闭。

3. **笔记页 / 泛页必须区分**（这一步极易写错）：

| URL 形态 | 判定 | 理由 |
|---|---|---|
| `/explore/<24位id>` | **U** | 真实笔记页 |
| `/discovery/item/<id>` | **U** | 真实笔记页（rednote 国际域名同） |
| 裸 `/explore`、`/explore?language=xx` | C | 列表页，无内容 |
| `/user/profile/<id>` | C | 个人主页，非一篇攻略 |

**踩过的坑**：第一版正则写成 `r"xiaohongshu\.com/(explore|discovery/item)/?$"`，
把 `/explore/641a...` 真实笔记页也判成了泛页 → **真源被误杀**。
必须用 `(\?|/?$)` 严格匹配"路径到此为止"，并单独处理带 query 的列表页。

**使用原则（写进报告里了）**：U 级源只做**交叉印证**（多篇笔记都说某店好 → 可信度提升），
**绝不单独作为票价 / 开放时间 / 预约规则的依据**——那些一律以 A 级官方源为准。

**遗留局限**：小红书笔记页因登录墙，摘要常为空，即便抓到 URL 也难提取正文。
若要真正读取笔记内容，需另接小红书原生签名直连（TripStar 的 `xhs_service.py` 方案，需 Cookie）。

## 陷阱 8：模块正文含 `</script>` → 整页 JS 崩溃（**最隐蔽的一个**）

先生 2026-09-15 指示把地图**内嵌进报告**（单文件交付）。实现方式是
`md2html.py` 把模块正文序列化成 JSON 写进顶层脚本：

```js
const MODULES = [{"name": "路线地图", "body": "...<script>...</script>..."}, ...];
```

**问题**：内嵌的地图片段天然含 3 处 `</script>`。HTML 规范规定，
浏览器解析 `<script>` 内容时**遇到 `</script` 就立即闭合**——
**不管它是不是在 JS 字符串里**。

后果：脚本块在第 1 处 `</script>` 处被截断 → `const MODULES = [...]` 变成
未闭合的语法 → **整页 JS 全崩**，报告和地图都渲染不出来。

更麻烦的是：**这个 bug 用肉眼看不出来**，因为源码看起来完全正常；
也没法靠"打开看一眼"发现——`innerHTML` 不会报错，只是白屏。

**修法**（`md2html.py` 的 `convert()`）：

```python
mods_json = _json.dumps(modules, ensure_ascii=False).replace("</", "<\\/")
html = HTML.format(..., modules=mods_json)
```

`<\/` 在 JS 字符串里与 `</` 完全等价，但浏览器 HTML 解析器不再识别为闭合标签。

**自检方法**（新写报告后必跑）：

```python
i = h.find('const MODULES = '); j = h.find('];\nconst nav', i)
assert h[i:j].lower().count('</script') == 0, "模块 JSON 里仍有裸 </script！"
```

**同类风险清单**（凡要写进 `<script>` 的字符串都要过一遍）：
- `</script>`（致命，必须转义）
- `<!--`：在脚本里会被当注释起头，也应转义为 `<\!--`
- 模板字符串里写 `<script>` 开标签：**同样会破坏**，注释里也不行。
  本 skill 就踩过——`// 通过 innerHTML 注入的 <script> 不会执行` 这行注释
  直接让脚本块提前结束。

## 陷阱 9：`innerHTML` 注入的 `<script>` 不会执行

模块化版面用 `d.innerHTML = m.body` 注入模块内容。但按 HTML 规范，
**通过 `innerHTML` 插入的 `<script>` 不会被执行**——地图永远不初始化。

**修法**（`md2html.py` 的 `injectHTML()`）：用 `DOMParser` 解析后
手动重建 script 节点再插入：

```js
const doc = new DOMParser().parseFromString('<div id="__root__">'+html+'</div>', 'text/html');
const scripts = [];
root.querySelectorAll('script').forEach(s => { scripts.push(s); s.remove(); });
while (root.firstChild) target.appendChild(root.firstChild);
scripts.forEach(old => {
  const s = document.createElement('script');
  for (const a of old.attributes) s.setAttribute(a.name, a.value);
  s.textContent = old.textContent;
  if (s.src) s.async = false;      // 保证顺序：代理配置必须先于 SDK
  target.appendChild(s);
});
```

**配套问题**：Tab 切换时地图模块初始 `display:none`，容器尺寸为 0，
`fitBounds` 算不出正确视野。修法：

1. `map_html.py` 暴露 `window.__rebuildMap__`
2. `md2html.py` 的 `show(i)` 里 `setTimeout(window.__rebuildMap__, 80)`
3. 首次渲染也要延迟调一次

**SDK 异步竞态**：腾讯 GL JS 是异步加载的，初始化代码可能在 SDK 就绪前执行。
`map_html.py` 内嵌片段用轮询兜底：

```js
var __tries = 0;
function boot(){
  if (typeof TMap === "undefined") {
    if (++__tries > 100) { /* 显示降级提示 */ return; }
    return setTimeout(boot, 100);
  }
  initMap();
}
```

## 费用模型：两层区间（先生 2026-09-15 指示）

先生原话：**「重新计算费用，我觉得费用有问题，你直接列出『预计费用合计区间』给出最小费用和最大费用」**。

**旧模型的三个硬伤**：
1. 租车/油费/停车/住宿是**每车（每间房）**成本，却被混进"人均"口径相加；
2. 每项只取单一估计值，**国庆租车浮动极大（¥150/天 平日 → ¥250~480/天 假日）**，
   单一值严重低估风险；
3. 结论是一个精确到个位的数字，给人"很准"的错觉。

**新模型**：拆成两层，每层给区间。

| 层 | 含义 | 项 |
|---|---|---|
| `FIXED_COST` | **每车固定**（含 1 间房，不随人数变） | 租车、租车全险、油费、过路费/停车、住宿 |
