# 境外行程扩展（信源 / 地图 / 地理编码 的双轨方案）

> 适用场景：目的地在中国境外（日韩、东南亚、欧洲、北美……）。
> 本文定义 trip-plan 的**双轨机制**：**境内走腾讯地图 + 中文攻略源，境外走 OSM 生态 + 维基系信源**。
> 核对时间：2026-09-17。各服务条款随时可能变，落地前请复核官方页面。

---

## ⚠ 勘误与更新（2026-09-17 实测）

**本文原先的主方案（Wikivoyage + Nominatim）在本环境完全不可用**，已按实测结果修正。
以下结论来自 `scripts/overseas_research.py` 的连通性探测，读者**不要跳过这一节**：

| 原方案组件 | 实测 | 现方案 |
|---|---|---|
| `en.wikivoyage.org`（主力信源） | ❌ **http=000 被墙** | 改用 **anysearch 检索境外攻略**（与境内同一通道） |
| 整个 Wikimedia（含 `en.wikipedia.org` / `commons`） | ❌ 被墙 | 同上；`wikidata` 标签**只能读 OSM 里的属性值**，不能回查 Wikipedia |
| `nominatim.openstreetmap.org` / `.de` | ❌ 被墙 | **改用 Photon**（`photon.komoot.io`）—— 还额外返回 `extent` bbox，更适合本用途 |
| `tiles.openstreetmap.org` / `opentopomap` / `stadiamaps` | ❌ 被墙 | OpenFreeMap / CARTO（`basemaps.cartocdn.com`） |
| `overpass-api.de` | ✅ 通 | 保持 |
| `overpass.private.coffee` | ✅ 通 | 作为**备用镜像**（主站超时自动切） |
| `router.project-osrm.org` | ✅ 通 | 保持 —— **真实道路**距离/时长，比境内「直线 ×1.35」估算更准 |
| `tiles.openfreemap.org` / `demotiles.maplibre.org` | ✅ 通 | 保持 |
| `api.open-meteo.com` | ✅ 通 | 保持（境内境外通用） |

> **教训（值得写进方法论）**：设计任何依赖境外服务的方案时，
> **先做可达性探测，再写代码**。Wikivoyage + Nominatim 看起来最正统、
> 文档最完备，但在本环境里两个都不可达，等于零。
> 一个 `curl -o /dev/null -s -w "%{http_code}"` 就能省下几小时返工。

**落地脚本**：`scripts/overseas_research.py`（`geocode` / `pool` / `route` / `all`）。
其 `to_places()` 输出与国内 `places.json` **同构**，可直接喂 `planner_multi.py`。

## 0. 先说红线：为什么必须双轨

| 轨道 | 底图 | 地理编码 / POI | 信源 |
|---|---|---|---|
| **境内** | 腾讯地图 GL JS（免 Key 代理模式）／高德／百度／天地图，或**内联 SVG 示意图** | 腾讯 / 高德 | 中文攻略、本地宝、政府站、小红书 |
| **境外** | MapLibre GL + OpenFreeMap（免 Key，见下） | **Photon + Overpass**（免 Key） | OSM 属性 + `wikidata`/`wikipedia` 标签 + anysearch 检索攻略 |

**境内**：只能走腾讯 / 高德 / 百度 / 天地图。**禁止** Google Maps、Apple Maps、Mapbox、
Leaflet + OpenStreetMap、境外版 Bing、直接引境外瓦片。

**境外**：反过来 —— 腾讯 / 高德 / 百度**在境外几乎没有数据**（越境底图也不合规），
必须换成 OSM 生态。**此时 OSM 不但可用，还是最优解**。

判断依据就一条：**目的地在哪里，就用哪一轨的底图与信源。**
跨国行程（如中国 → 老挝）应**分段处理**，不要试图用一张图覆盖。

## 1. 境外地图：免 Key 方案排序

### 1.1 首选：OpenFreeMap（零配置、零 Key、可商用）

```
https://tiles.openfreemap.org/styles/liberty     # 经典街道风
https://tiles.openfreemap.org/styles/bright      # 明亮彩色
https://tiles.openfreemap.org/styles/positron    # 浅灰极简（做数据叠加最好）
https://tiles.openfreemap.org/styles/dark        # 深色
https://tiles.openfreemap.org/styles/fiord       # 蓝调深色
```

- **无 Key、无注册、无请求上限、允许商用**，MIT 许可，数据来自 OSM（ODbL）。
- 基于 OpenMapTiles schema，全球矢量瓦片，**每周重建**。
- **MapLibre 会自动加署名**（用其他客户端或印刷/视频时必须手工加
  `OpenFreeMap © OpenMapTiles Data from OpenStreetMap`）。
- 靠捐赠维持、**无 SLA**。生产环境建议在 style 里**配一个备用瓦片源**，并对失败做降级。
- 全栈开源、可自托管（planet 下载 + 自建 nginx）。

### 1.2 次选：CARTO Basemaps（做数据可视化背景最干净）

```
https://basemaps.cartocdn.com/gl/positron-gl-style/style.json
https://basemaps.cartocdn.com/gl/voyager-gl-style/style.json
https://basemaps.cartocdn.com/gl/dark-matter-gl-style/style.json
```

无 Key 可用，但 CARTO 期望**商用或高流量前先注册/联系**。不可自托管。

### 1.3 其他可选

| 方案 | 形态 | Key | 备注 |
|---|---|---|---|
| **VersaTiles** | 托管的 style URL / 自托管 | 无 | OSM Shortbread schema，无请求限制，欧洲团队 |
| **Protomaps** | PMTiles 单文件 | 自托管无限 / 托管 API 需 Key | 可放 Cloudflare R2 + Worker，成本极低 |
| **OSMF 官方矢量瓦片** | `https://vector.openstreetmap.org/…mvt` | 无 | Shortbread schema，OSMF 提供，遵守 fair use |
| **Stadia Maps / Stamen** | 托管 | **需 Key** | Stamen Toner/Terrain/Watercolor 的现居所；非商用有免费额度 |
| **MapTiler Cloud** | 托管 | **需 Key** | 免费额度较小；附地理编码/高程/静态图 |
| **ESRI World Imagery** | 栅格卫星瓦片 | 无（有条款约束） | `…/World_Imagery/MapServer/tile/{z}/{y}/{x}`，做卫星底图时用，注意 Esri 条款 |

**不要考虑**：**Bing Maps（正在退役）**、**Mapbox GL JS v2+**（许可把客户端绑死在 Mapbox）。

### 1.4 ⚠ 最大的坑：不要用 `tile.openstreetmap.org`

这是本项目最容易犯的错误 —— 很多人以为「OSM 是开源的所以随便用」。**不是。**

OSMF 的 [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) 明确规定
`tile.openstreetmap.org` **只服务于 OSM 自身的浏览与制图社区**：

- ❌ **禁止批量下载（scrape）/ 预取**
- ❌ **明确不适合「有实质流量的分发型应用」**
- ❌ 必须发可识别应用的 `User-Agent`（库默认 UA 会被拦）+ 网页端须带 `Referer`
- ⚠️ best-effort、**无 SLA**，违规**可能被无预警封禁**
- 官方说法：QGIS 会话、内部 demo 可以；**产品不行**

→ **产品一律改用 OpenFreeMap / CARTO / VersaTiles / 自托管。**
这四家做的都是同一件事：把 OSM 数据重做成可商用的瓦片服务。

### 1.5 渲染库：MapLibre GL JS

- Mapbox GL JS **v1 的社区 fork**（Mapbox v2 闭源，许可绑定）。
- 与腾讯 TMap GL JS 的 API 形态不同（`Map` / `Marker` / `Source`+`Layer` 分离），
  但「**先配 style、再加 source、再加 layer**」的思路一致。
- 单文件 HTML 可内嵌 CDN：`https://unpkg.com/maplibre-gl/dist/maplibre-gl.js` + 对应 CSS。
- 署名控件：`new maplibregl.AttributionControl()`，OpenFreeMap 会自动填。

## 2. 境外地理编码与 POI

### 2.1 Nominatim（地名 → 坐标）

```
https://nominatim.openstreetmap.org/search?q=…&format=jsonv2
https://nominatim.openstreetmap.org/reverse?lat=…&lon=…&format=jsonv2
```

**使用政策（必须遵守，否则 IP 段被封）**：

- **绝对上限 1 请求/秒**（不是建议，是硬限制）
- **必须带可识别的 `User-Agent`**，形如
  `trip-plan/1.0 (+https://example.org; contact: you@example.org)`；
  `python-requests/x.y`、`curl/x.y` 这类默认 UA **会被静默拦截**
- 必须**清晰署名** `© OpenStreetMap contributors`（链到 copyright 页）
- **明确禁止**：自动补全（autocomplete）、网格化系统查询、批量下载某区域全部 POI、
  抓 `/details` 页、转售地理编码结果
- 批量场景正解：**下载 Geofabrik 区域 PBF 自建**，或自建 Nominatim

> 本项目在地图里做「景点名 → 坐标」的批量编码时，**1 req/s 是硬约束**：
> 30 个景点要跑 30 秒。要么接受，要么改用 Overpass / 预置坐标表。
> **不要用多线程绕过** —— 那是政策明令禁止的行为。

### 2.2 Overpass API（按 OSM tag 查 POI，比地名搜索更强）

```
https://overpass-api.de/api/interpreter     # POST Overpass QL
https://overpass-turbo.eu/                  # 浏览器里试查询再落地
```

- 免 Key。**约 1 万次查询/天 + 1GB/天**，同会话并发是 slot 制，超了返回 429。
- 一次能拿到**一整个片区的景点/餐厅/车站**，比逐条地名搜索高效得多。
- 返回的 tag 里常含 `wikidata=` / `wikipedia=`，**可直接与维基系信源打通**。
- 常用查询形态（找某城市所有景点类要素）：
  `[out:json][timeout:60]; area["name"="Kyoto"]->.a; node(area.a)["tourism"~"attraction|museum"]; out;`

### 2.3 批量下载（正经做法）

- **Geofabrik** `https://download.geofabrik.de/` —— 按国家/地区分片的 `.osm.pbf`，**日更**。
- **Planet OSM** `https://planet.openstreetmap.org/` —— 全球全量。
- 本地用 `pyrosm` / `osmium` 过滤，比任何 API 都快且完全不打扰公共服务器。

**ODbL 义务**（只要用了 OSM 数据就适用）：署名 + 若发布「衍生数据库」需同许可共享。
「只用来出图」属于 Produced Work，**不要求开源**。

## 3. 境外信源

### 3.1 Wikivoyage —— 境外行程的第一信源

**为什么它比中文攻略更适合境外**：

- **142,000+ 篇**，覆盖国家 / 地区 / 城市 / 街区，20+ 语言。
- **所有条目结构统一**，子标题固定：
  `Understand`（背景）/ `Talk`（语言）/ `Get in`（怎么去）/ `Get around`（怎么转）/
  `See`（看什么）/ `Do`（做什么）/ `Buy` / `Eat` / `Drink` / `Sleep` / `Stay safe`。
  → **无需写复杂爬虫**，按标题切段就能稳定抽到「交通/景点/吃饭/住宿/安全」。
- `See` / `Do` / `Eat` 段里的每一条**都带 GPS 坐标**，可直接喂给地图。
  几乎所有条目还带 **Wikidata ID**，可与 Wikidata / Wikipedia 打通做知识图谱。
- 由真实旅行者维护、**不含商业广告**。
- 许可 **CC BY-SA 4.0**：需署名作者 + 链接回原文 + 改动需同许可。
- API：`https://<lang>.wikivoyage.org/w/api.php`（Action API）与 `/w/rest.php/v1/`。
  **使用限制**：≤ **1 页 / 30 秒**、serial（非并行）请求、带可联系 UA、自动客户端须用 `maxlag`。

### 3.2 其他

| 信源 | 用途 | 许可 / 限制 |
|---|---|---|
| **Wikipedia** | 百科背景、历史事实核对 | CC BY-SA；同一 MediaWiki 使用政策 |
| **Wikidata** | 跨库消歧（同名景点）、结构化属性、国家公园等 | CC0（最宽松） |
| **Wikimedia Commons** | 可复用图片 | 逐图许可不同，需核对 |
| **各国官方旅游局** | 签证、交通票、官方活动排期 | 各自条款；**权威度最高，优先级同境内 A 级** |
| **各国铁路/公交官网** | 时刻与票价（如 JR、DB、SNCF） | 各自条款；**票价唯一权威源** |
| **OSM `opening_hours` / `website` tag** | 开放时间与官网（时效性一般，需交叉验证） | ODbL |

### 3.3 境外信源分级映射

沿用境内的 A / U / C / D 四档，境外映射如下：

| 等级 | 境外对应 |
|---|---|
| **A 权威** | 官方旅游局、政府站、铁路/公交官网、Wikipedia、Wikivoyage、Wikidata |
| **U 用户实拍** | 境外 UGC 具体帖子（须是具体页面，不是列表页）—— 仅作交叉印证 |
| **C 待核** | 境外 OTA、论坛帖、旧年份攻略、聚合站 |
| **D 噪声** | 与目的地无关内容 |

> **境内「小红书 U 级」在境外基本失效**，但 **Wikivoyage 因为结构统一 + 有坐标，
> 实际替代了境内「本地宝 + 小红书」两者的一部分职能**，可直接作为 A 级使用。

## 4. 落地检查清单（境外目的地）

写行程前逐项确认：

- [ ] **目的地在中国境外** → 本文件适用（境内行程请走腾讯地图轨）
- [ ] 地图用 **OpenFreeMap / CARTO / VersaTiles**，**没有**用 `tile.openstreetmap.org`
- [ ] 渲染库用 **MapLibre GL JS**（不是 Mapbox GL JS v2+）
- [ ] 底图上**有 OSM 署名**（通常由 MapLibre 自动加）
- [ ] 地理编码若用 Nominatim：**限速 1 req/s** + 自定义 `User-Agent` + 结果**本地缓存**
- [ ] 没用 Nominatim 做自动补全 / 网格化批量查询 / 转售
- [ ] 信源里 **Wikivoyage 已纳入**，且按 A 级处理
- [ ] 用 Wikivoyage 内容时**保留署名与原文链接**
- [ ] 跨城交通以**目的地国铁路/公交官网**为准，不用第三方聚合站当唯一来源
- [ ] 跨国行程**分段处理**（中国段走境内轨，境外段走境外轨）

## 5. 与现有脚本的关系

| 脚本 | 境内 | 境外 |
|---|---|---|
| `map_html.py` | ✅ 腾讯地图 GL JS，免 Key 代理 | ❌ 不可用（越境不合规 + 无数据） |
| 检索 | `research.py` + anysearch 中文源 | 需换成 Wikivoyage API + Nominatim/Overpass；anysearch 仍可用于中文跨境攻略 |
| 地理编码 | 坐标表 / 腾讯 | **Nominatim（1 req/s）或 Overpass** |
| 天气 | ✅ `weather.py`（Open-Meteo 全球覆盖，**无需改动**） | ✅ 同左 |
| 拥挤度 | ✅ `crowd_research.py`（中文 UGC 平台） | ⚠️ `site:xiaohongshu.com` 类定向失效，需换境外 UGC 源 |

> **`weather.py` 是全项目唯一一套境内/境外通用的层** —— Open-Meteo 免 Key、全球覆盖、
> 支持任意时区（`timezone=auto`）。境外行程不需要改任何东西。

## 6. 一句话总结

**境内走腾讯 + 中文攻略；境外走 MapLibre + OpenFreeMap + Nominatim/Overpass + Wikivoyage。
两边唯一同构的层是天气。最大的坑是把 `tile.openstreetmap.org` 用进产品 ——
OSM 的（数据）是自由的，OSMF 的（瓦片服务器）不是。**
