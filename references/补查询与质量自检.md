# 补查询与质量自检（gapfill）

> 借鉴来源：`weekend-city-trip` 的「质量检查 → 补查询触发 → 补查询执行 → 二次检查」闭环。
> 本项目把它从「**章节条数够不够**」改造成「**情报方向缺不缺**」——
> 因为做行程需要的不是更多条数，而是**几类平时搜不到、但会直接毁掉行程的信息**。

---

## 1. 为什么要单独做一层补查询

默认检索包（`research.py` 的 17 组查询）解决的是**存量问题**：

> 「福州有哪些景点？」「门票多少？」「怎么去？」

这些信息多、且到处都有，检索命中率天然很高。但它们**答不了**：

> 「鼓山现在还开着吗？」「国庆要不要预约？」「上山的路封不封？」
> 「这个月去，能看见什么？」

后者是**增量信息**，特征有三个：

1. **只有权威源（政府站 / 景区公告 / 地方媒体）会发**，攻略站不转载；
2. **时效极强**，三个月前的公告可能已经失效；
3. **零命中也毫不显眼** —— 报告里少一段话，你看不出来，
   但它可能就是「白跑一趟」与「顺利玩到」的差别。

**所以不能靠「章节字数够不够」触发，只能靠「方向有没有命中」触发。**

---

## 2. 八个方向与触发阈值

`gapfill.py` 的 `GAP_PACKS` 定义了八个方向。判定方式是：
把全部信源的**标题 + 摘要**拼成一个大字符串，
统计每个方向的**特征词命中次数**，低于阈值即为缺口。

| 方向 | key | 为什么重要 | 特征词（节选） | 阈值 | 优先级 |
|---|---|---|---|---|---|
| **运维动向** | `ops` | 闭园/维修/施工 → 白跑一趟 | 闭园、维修、施工、暂停开放、封闭、改造、恢复开放 | 2 | 🔴 必补 |
| **预约限流** | `booking` | 法定假日不预约进不去 | 预约、限流、实名、名额、放号、免预约 | 3 | 🔴 必补 |
| **交通管制** | `traffic` | 到了山门口才发现封路 | 管制、停车、限行、单行、封路、摆渡、接驳 | 2 | 🟡 建议补 |
| **新开试运营** | `newopen` | 半年内攻略不收录，但常是最大惊喜 | 新开、开业、试运营、全新、首发、开街 | 1 | 🟡 建议补 |
| **季节限定** | `season` | 花期/红叶决定这趟值不值 | 花期、最佳观赏、限定、当季、盛开、红叶、蓝眼泪 | 2 | 🟡 建议补 |
| **票价变动** | `price` | 攻略票价常滞后 2~3 年 | 旺季、淡季、涨价、调价、免费开放、价格调整 | 2 | 🟢 可选 |
| **避坑提醒** | `pitfall` | 宰客/骗局只有 UGC 会说 | 避坑、宰客、骗、套路、坑人、不建议 | 2 | 🟡 建议补 |
| **船班航线** | `ferry` | 海岛受风浪影响，班次会停 | 船班、轮渡、航线、码头、停航、船票、客滚 | 2 | 🟡 建议补（**有海岛才评估**） |

### 门控方向（`when_any`）

`ferry` 带 `when_any` 门控：只有当信源里**已经出现**「海岛 / 航线 / 船班 / 码头 / 离岛」
等词时才评估该方向。内陆目的地不会因为「没查到船班」而被判为缺口。

> 这是必要的设计 —— 否则每个内陆城市都会稳定地在 `ferry` 上判缺失，
> 白白浪费一轮查询额度。

## 3. 补查询的三道闸门

补查询本身**很容易把报告搞脏**（召回到邻市、甚至完全无关的内容）。
所以命中结果要过三道闸门才入库：

### 闸门 1：URL 去重
按「去协议 / 去 www / 去 query / 去尾斜杠」归一化，与已有信源对比。

### 闸门 2：相关性过滤（`is_relevant`）

**这一步最关键。** 补查询最容易踩的坑是：

> query 里带了地名，但召回的是「XX 省其他城市」的内容，
> 而且因为是**政府站 / 官媒域名**，反手拿到 A 级 —— 越权威越危险。

规则：
1. **黑名单域名直接丢**：`NOISE_DOMAINS`（央视综合新闻频道、其它省市政务站、
   税务总局、facebook 等）
2. **标题 + 摘要必须出现目的地名（或其别名）**，否则丢

别名用 `--alias` 传入。例：
- 平潭 → `--alias 福州`
- 永泰 → `--alias 福州 --alias 云顶 --alias 青云山 --alias 嵩口`

> **实测数据**（福州 / 平潭 / 永泰，2026-09-17）：
> 补查询共新增 147 条，其中 **84 条被相关性闸门丢弃**（占 57%）。
> 也就是说：**不加这道闸门，补查询有一半以上的产出是噪声。**
> 而且被丢掉的里包含「湖北宜都闭园公告」「湖南景区闭园」「台湾太鲁阁暂停开放」
> 「敦煌景区公告」这类**看起来极其对题、实际完全无关**的内容。

### 闸门 3：迭代上限（**最多 2 轮**）

- 每轮补查询数有上限（`--max-queries`，默认 8）
- 最多 2 轮（第 1 轮 `run`，第 2 轮 `fill`）
- 第 2 轮后仍不达标 → **写「信息有限」并交付，不编造**

> **实测**：永泰的 `booking`（预约限流）方向补了两轮仍只有 1 条命中，
> 低于阈值 3。脚本如实输出：
> 「补查后命中 1 条，仍低于阈值 3 —— 该方向信息有限」，
> 并要求报告写「出行前请致电景区确认」。
> **这是正确的行为** —— 一个只有 4 个查询额度的小县城，
> 本来就不该有「完整的预约政策」可言。承认信息有限比编一段话强。

## 4. 用法

```bash
export ANYSEARCH_API_KEY=as_sk_xxx
G=scripts/gapfill.py

# 只看缺口，不联网（写完报告后自查用）
python $G check --graded ./ly/graded.json --city 福州

# 执行补查询并原地合并进 graded.json，同时写出 gaps.json
python $G run --graded ./ly/graded.json --city 福州 \
    --year 2026 --month 10 --out ./ly

# 第二轮（带别名，用于上一轮仍有必补方向未解除时）
python $G fill --graded ./yt/graded.json --city 永泰 \
    --year 2026 --month 10 --alias 福州 --alias 云顶 --alias 青云山 --out ./yt

# 补救：补查询先跑、后来才加相关性过滤时，清理已入库的无关条目
python $G prune --graded ./ly/graded.json --city 福州 --alias 福州
```

### 子命令

| 命令 | 行为 |
|---|---|
| `check` | 只做缺口判定，输出报告，**不联网** |
| `fill` | 执行一轮补查询并合并 |
| `run` | `check`（打印补前状态）→ `fill` → 报告 |
| `prune` | 用相关性规则清理**已入库**的 `source=="gapfill"` 条目 |

### 产出

- `graded.json` —— 原地合并，新增条目带 `source: "gapfill"` 与 `gap_key`
- `gaps.json` —— 缺口报告：`before / after / added / dropped_irrelevant / queries_run / gaps[] / log[]`

### 状态语义

| status | 含义 |
|---|---|
| `covered` | 本来就有信息，无需补 |
| `filled` | 补查后命中达标，缺口已解除 |
| `still_gap` | 补查后仍不达标 → **报告须写「信息有限」** |
| `gap` | 判为缺口（`check` 模式下尚未补） |
| `skipped` | 门控未通过（如内陆城市不做船班） |
| `deferred` | 优先级不在本轮范围内 |

## 5. 报告里怎么写

补查询的产出**不能直接铺在正文**（先生的要求：报告给结论，不给推导过程）。
落法是：

**结论入正文，证据入折叠。**

- **正文**：按「运维 / 台风 / 新开 / 季节」分组，每组写
  「**发生了什么 → 对我这趟的影响 → 怎么办**」三段。
  重点是第三段 —— 每条动向都给出**具体的替代方案**，
  而不是只报一条新闻。
- **折叠**：每组下面挂 `<details><summary>信源</summary>`，列出可追溯 URL。
- **自检表**：加一张「补查询覆盖自检」表，把八个方向的状态如实列出。
  **`still_gap` 必须显式写出来**，这是报告诚实性的凭据。

> 一句话：**补查询的价值不在「多找到几条」，而在「把『白跑一趟』这个风险显式摆到台面上」。**

## 6. 与 weekend-city-trip 的对照

| 维度 | weekend-city-trip | 本项目（trip-plan） |
|---|---|---|
| 触发依据 | 章节条数 < 最低信息密度 | **情报方向的命中次数 < 阈值** |
| 触发对象 | 「演唱会 < 3 场」这类**存量不足** | 「闭园维修零命中」这类**增量缺失** |
| 补查询方向 | 固定 11 个调查方向 | **8 个风险/动向方向**（可门控） |
| 噪声处理 | 靠"跨城市噪声 > 30%"事后识别 | **入库前的相关性闸门**（域名黑名单 + 地名必现） |
| 迭代控制 | 最多 2 轮，每轮 ≤ 5 query | 最多 2 轮，每轮 ≤ 8 query |
| 不达标出口 | 「标注信息有限交付」 | 同左，**并在报告中显式列出未解除的方向** |
| 产出形态 | 报告章节 | 报告章节 **+ `gaps.json` 机器可读自检** |
